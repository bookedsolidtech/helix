# @helixui/react Test Suite

Vitest browser-mode tests for all React wrappers generated by `@lit/react`.

## Running the tests

```bash
# From the monorepo root
pnpm run test:react

# From the package
pnpm --filter=@helixui/react run test

# Watch mode
pnpm --filter=@helixui/react run test:watch

# Type-check test files
pnpm --filter=@helixui/react run type-check:test
```

## Test suites

| File | What it tests |
|---|---|
| `render.test.tsx` | All 97+ wrappers render a custom element in the DOM |
| `props.test.tsx` | Props are forwarded to the web component as JS properties |
| `events.test.tsx` | `onHxClick`, `onHxChange`, etc. map to the correct custom events |
| `refs.test.tsx` | React refs resolve to the underlying `HTMLElement` |
| `ssr.test.tsx` | `'use client'` directive present in all wrappers, `displayName` set |
| `types.test-d.ts` | TypeScript type assertions compile without errors |

## Environment

Tests run in **Vitest browser mode with Playwright (Chromium)**. This means:
- Tests execute inside a real browser, not jsdom
- Custom elements (`hx-*`) actually register and render their shadow DOM
- Web APIs (ResizeObserver, IntersectionObserver, etc.) are available

## Adding tests for a new component

1. Open `test/cem-parser.ts` and add metadata for the new component:
   ```ts
   {
     name: 'HxNewComponent',
     tagName: 'hx-new-component',
     events: ['hx-change'],
     props: { label: 'Example', disabled: false },
   },
   ```

2. Import the component in the relevant test file (e.g. `props.test.tsx`):
   ```tsx
   import { HxNewComponent } from '../src/components/HxNewComponent/index.js';
   ```

3. Add `describe('HxNewComponent', ...)` blocks following the existing patterns.

The `render.test.tsx` auto-discovers new components from `src/index.ts` — no changes needed there.

## Debugging failing tests

Run a single test file in verbose mode:
```bash
pnpm --filter=@helixui/react run test -- test/render.test.tsx --reporter=verbose
```

Check the browser console for errors:
```bash
# Vitest browser mode opens Playwright — set headless: false in vitest.config.ts temporarily
# to watch tests run in an actual browser window
```

## Architecture

- **`vitest.config.ts`** — browser mode config with `@vitejs/plugin-react`
- **`test/setup.ts`** — prevents duplicate custom element registration errors
- **`test/utils.tsx`** — `render()` helper wrapping `ReactDOM.createRoot`
- **`test/fixtures/sample-components.ts`** — components selected for detailed testing
- **`test/cem-parser.ts`** — handcoded metadata (CEM file not required)
- **`tsconfig.test.json`** — TypeScript config that includes the test directory

## Known limitations

- `types.test-d.ts` requires `pnpm run type-check:test` (separate from `type-check`)
- Some components may render with console warnings about missing required attributes — these are informational and do not fail tests
- SSR "use client" check uses `import.meta.glob` with raw source, which reads TypeScript before transpilation
