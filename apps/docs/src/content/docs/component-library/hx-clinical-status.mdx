## Overview

`hx-clinical-status` is a clinical alert indicator designed specifically for healthcare alert fatigue prevention. It standardizes the visual and semantic presentation of four severity levels — `info`, `warning`, `critical`, and `emergent` — to reduce cognitive overload from inconsistent color and icon combinations across enterprise healthcare interfaces.

Unlike a general-purpose `hx-alert`, this component enforces clinical severity semantics: `critical` and `emergent` statuses require explicit acknowledgment, automatically use assertive `role="alert"` for immediate screen reader announcement, and default to `persistent` behavior (surviving page navigation).

**Use `hx-clinical-status` when:** communicating clinical patient safety alerts, medication conflicts, lab result flags, or any healthcare notification where standardized severity presentation is required to comply with alert fatigue prevention guidelines.

**Use `hx-alert` instead when:** the notification is a general application-level message (form errors, success confirmations, informational notices) without clinical safety implications.

## Basic Usage

Minimal HTML snippet — no build tool required:

```html
<!-- Informational clinical notice -->
<hx-clinical-status
  severity="info"
  message="Lab results available for Patient #4821."
></hx-clinical-status>

<!-- Warning requiring attention -->
<hx-clinical-status
  severity="warning"
  message="Medication interaction detected. Review before dispensing."
  dismissible
></hx-clinical-status>

<!-- Critical — requires acknowledgment -->
<hx-clinical-status
  severity="critical"
  message="Patient allergy conflict: Penicillin order requires immediate review."
  dismissible
></hx-clinical-status>

<!-- Emergent — immediate action required -->
<hx-clinical-status
  severity="emergent"
  message="Code Blue — Room 214-B. Immediate response required."
></hx-clinical-status>
```

Listen for dismiss and acknowledgment events:

```javascript
const status = document.querySelector('hx-clinical-status');

status.addEventListener('hx-dismiss', () => {
  console.log('Status dismissed');
  status.remove();
});

status.addEventListener('hx-acknowledge', (e) => {
  console.log('Acknowledged:', e.detail.severity, '— persistent:', e.detail.persistent);
});
```

## Properties

| Property      | Attribute     | Type                                              | Default  | Description                                                                                                                                                                                              |
| ------------- | ------------- | ------------------------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `severity`    | `severity`    | `'info' \| 'warning' \| 'critical' \| 'emergent'` | `'info'` | Clinical severity level. Controls visual styling and ARIA semantics. `critical` and `emergent` use `role="alert"` (assertive); `info` and `warning` use `role="status"` (polite). Reflects to attribute. |
| `message`     | `message`     | `string`                                          | `''`     | Primary status message text displayed as the main content of the indicator.                                                                                                                              |
| `dismissible` | `dismissible` | `boolean`                                         | `false`  | When true, shows a dismiss button. For `critical` and `emergent`, an acknowledge button appears first — dismissal requires acknowledgment. Reflects to attribute.                                        |
| `persistent`  | `persistent`  | `boolean`                                         | `false`  | Whether the status survives page navigation. Defaults to `false` for `info`/`warning` and `true` for `critical`/`emergent` if not set explicitly. Reflects to attribute.                                 |
| `icon`        | `icon`        | `string`                                          | `''`     | Optional custom icon name. When empty, a default severity-appropriate icon is used.                                                                                                                      |
| `compact`     | `compact`     | `boolean`                                         | `false`  | Compact mode for dense clinical UIs (patient dashboards, bedside displays). Reduces padding, font size, and icon size. Reflects to attribute.                                                            |

## Events

| Event            | Detail Type                                           | Description                                                                                               |
| ---------------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `hx-dismiss`     | `void`                                                | Dispatched when the user dismisses the status. `bubbles: true, composed: true`.                           |
| `hx-acknowledge` | `{ severity: ClinicalSeverity; persistent: boolean }` | Dispatched when the user acknowledges a `critical` or `emergent` status. `bubbles: true, composed: true`. |

```javascript
document.querySelector('hx-clinical-status').addEventListener('hx-acknowledge', (e) => {
  const { severity, persistent } = e.detail;
  // Log to clinical audit trail
  auditLog.record({ action: 'alert_acknowledged', severity, persistent });
});
```

## Accessibility

`hx-clinical-status` is purpose-built for WCAG 2.1 AA compliance in healthcare contexts where alert fatigue prevention is a patient safety requirement. It follows the ARIA APG alert and status patterns.

| Topic          | Details                                                                                                                                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ARIA role      | `role="alert"` on the host for `critical` and `emergent` severity — triggers immediate assertive announcement. `role="status"` for `info` and `warning` — announces politely without interrupting the user.         |
| Severity label | A visually-hidden severity prefix (`"Info:"`, `"Warning:"`, `"Critical:"`, `"Emergent:"`) is prepended to the message content. This ensures the severity level is not conveyed by color or icon alone (WCAG 1.4.1). |
| Acknowledgment | `critical` and `emergent` statuses display an `"Acknowledge"` button before the dismiss button. This enforces that clinical staff explicitly confirm receipt of urgent alerts before they can be dismissed.         |
| Keyboard       | `Tab` navigates to the acknowledge and dismiss buttons. `Enter` or `Space` activates them.                                                                                                                          |
| Focus          | No automatic focus movement on render. The assertive live region announces the alert to screen reader users without requiring focus change.                                                                         |
| Color alone    | Severity is communicated via ARIA role, a visually-hidden text prefix, and distinct severity-appropriate icons — never by color alone. Satisfies WCAG 1.4.1 (Use of Color).                                         |
| Reduced motion | No animation is applied to the status indicator itself. If motion is added via CSS, respect `prefers-reduced-motion: reduce`.                                                                                       |
| WCAG           | Meets WCAG 2.1 AA. SC 1.4.1 (Use of Color), SC 4.1.2 (Name, Role, Value), SC 1.3.1 (Info and Relationships). Designed for healthcare HIPAA-adjacent environments requiring standardized alert presentation.         |

### Alert Fatigue Prevention Pattern

Always use consistent severity levels across the application. The four-tier model maps directly to clinical urgency:

| Severity   | Clinical Use Case                                          | ARIA Behavior              | Persistence Default |
| ---------- | ---------------------------------------------------------- | -------------------------- | ------------------- |
| `info`     | Lab results available, chart updated, routine notices      | `role="status"` (polite)   | Not persistent      |
| `warning`  | Medication expiry, consent renewal, near-threshold values  | `role="status"` (polite)   | Not persistent      |
| `critical` | Allergy conflicts, abnormal lab values, order errors       | `role="alert"` (assertive) | Persistent          |
| `emergent` | Code Blue, life-threatening conditions, immediate response | `role="alert"` (assertive) | Persistent          |

## Drupal Integration

```twig
{# my-module/templates/clinical-alert.html.twig #}
<hx-clinical-status
  severity="{{ severity|default('info') }}"
  message="{{ message }}"
  {% if dismissible %}dismissible{% endif %}
  {% if persistent %}persistent{% endif %}
  {% if compact %}compact{% endif %}
  {% if icon %}icon="{{ icon }}"{% endif %}
>
  {% if detail_content %}
    {{ detail_content }}
  {% endif %}
</hx-clinical-status>
```

Load the library in your module's `.libraries.yml`:

```yaml
helix-components:
  js:
    /libraries/helix/helix.min.js: { minified: true }
```

Handle dismiss and acknowledgment events in Drupal behaviors:

```javascript
Drupal.behaviors.helixClinicalStatus = {
  attach(context) {
    once('helixClinicalStatus', 'hx-clinical-status', context).forEach((el) => {
      el.addEventListener('hx-dismiss', () => {
        // Log dismissal to clinical audit trail via Drupal AJAX
        Drupal.ajax({
          url: '/api/clinical-alerts/dismiss',
          base: false,
          element: el,
        }).execute({ alertId: el.dataset.alertId });
        el.remove();
      });

      el.addEventListener('hx-acknowledge', (e) => {
        const { severity, persistent } = e.detail;
        // Log acknowledgment to clinical audit trail
        Drupal.ajax({
          url: '/api/clinical-alerts/acknowledge',
          base: false,
          element: el,
        }).execute({ alertId: el.dataset.alertId, severity, persistent });
      });
    });
  },
};
```

## Standalone HTML Example

Copy-paste this into a `.html` file and open it in a browser — no build tool needed:

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>hx-clinical-status example</title>
    <!-- @helixui/library is a private package — install via npm workspace, not CDN -->
    <!-- In your project: import '@helixui/library'; in your bundler entry point -->
  </head>
  <body
    style="font-family: sans-serif; padding: 2rem; display: flex; flex-direction: column; gap: 1.5rem; max-width: 600px;"
  >
    <!-- 1. Info: routine notice -->
    <hx-clinical-status
      id="info-status"
      severity="info"
      message="Lab results available for Patient #4821. No abnormal values."
      dismissible
    ></hx-clinical-status>

    <!-- 2. Warning: requires attention -->
    <hx-clinical-status
      id="warning-status"
      severity="warning"
      message="Medication interaction detected: Warfarin + Aspirin. Review before dispensing."
      dismissible
    ></hx-clinical-status>

    <!-- 3. Critical: requires acknowledgment -->
    <hx-clinical-status
      id="critical-status"
      severity="critical"
      message="Patient allergy conflict: Penicillin order for Jane Doe (MRN: 885521). Immediate review required."
      dismissible
    ></hx-clinical-status>

    <!-- 4. Emergent: life-threatening -->
    <hx-clinical-status
      id="emergent-status"
      severity="emergent"
      message="Code Blue — Room 214-B. Immediate clinical response required."
    ></hx-clinical-status>

    <script>
      // Log all dismissals and acknowledgments
      document.querySelectorAll('hx-clinical-status').forEach((el) => {
        el.addEventListener('hx-dismiss', () => {
          console.log(`[${el.severity}] dismissed`);
          el.style.opacity = '0';
          el.style.transition = 'opacity 0.2s';
          setTimeout(() => el.remove(), 200);
        });

        el.addEventListener('hx-acknowledge', (e) => {
          console.log(`[${e.detail.severity}] acknowledged — persistent: ${e.detail.persistent}`);
        });
      });
    </script>
  </body>
</html>
```
