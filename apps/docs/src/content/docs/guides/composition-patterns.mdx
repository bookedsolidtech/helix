# Component Composition Patterns

HELiX components are designed to be composed together. Individual components handle one concern well; composition patterns handle real-world UI requirements. This guide covers the most common patterns with HTML examples, component interaction notes, accessibility requirements, and Drupal Twig equivalents using Single Directory Components (SDC).

Each pattern shows the minimum viable composition first, then layers in additional components for richer experiences.

---

## Form Composition

Forms are the most common composition surface in healthcare applications — patient intake, scheduling, clinical data entry, and administrative workflows all rely on well-structured form patterns.

### Basic field group

`hx-form` wraps `hx-field` containers, which pair a label with a control. `hx-field` manages the label-to-control association, help text, and validation message layout automatically.

```html
<hx-form id="patient-intake" novalidate>
  <hx-field>
    <label slot="label" for="first-name">First name</label>
    <hx-text-input
      id="first-name"
      name="firstName"
      required
      autocomplete="given-name"
    ></hx-text-input>
  </hx-field>

  <hx-field>
    <label slot="label" for="last-name">Last name</label>
    <hx-text-input
      id="last-name"
      name="lastName"
      required
      autocomplete="family-name"
    ></hx-text-input>
  </hx-field>

  <hx-field>
    <label slot="label" for="dob">Date of birth</label>
    <hx-text-input
      id="dob"
      name="dateOfBirth"
      type="date"
      required
      autocomplete="bday"
    ></hx-text-input>
  </hx-field>

  <hx-button type="submit" variant="primary">Continue</hx-button>
</hx-form>
```

### Full form with select, checkbox, and validation

```html
<hx-form id="appointment-request" novalidate>
  <hx-field>
    <label slot="label" for="provider">Preferred provider</label>
    <hx-select id="provider" name="providerId" required>
      <option value="">Select a provider</option>
      <option value="p-001">Dr. Amara Osei, MD</option>
      <option value="p-002">Dr. Kenji Watanabe, MD</option>
      <option value="p-003">NP Sarah Lindqvist, APRN</option>
    </hx-select>
    <span slot="help-text">Choose from providers accepting new patients.</span>
  </hx-field>

  <hx-field>
    <label slot="label" for="visit-type">Visit type</label>
    <hx-select id="visit-type" name="visitType" required>
      <option value="">Select visit type</option>
      <option value="new">New patient</option>
      <option value="followup">Follow-up</option>
      <option value="urgent">Urgent care</option>
    </hx-select>
  </hx-field>

  <hx-field>
    <label slot="label" for="reason">Reason for visit</label>
    <hx-textarea id="reason" name="visitReason" rows="4" maxlength="500"></hx-textarea>
    <span slot="help-text"
      >Briefly describe your symptoms or reason for visit (500 characters max).</span
    >
  </hx-field>

  <hx-checkbox name="telehealth" value="yes">
    I am open to a telehealth appointment if in-person is unavailable.
  </hx-checkbox>

  <hx-field>
    <hx-checkbox-group name="contactMethod" legend="Preferred contact method" required>
      <hx-checkbox value="phone">Phone</hx-checkbox>
      <hx-checkbox value="email">Email</hx-checkbox>
      <hx-checkbox value="portal">Patient portal message</hx-checkbox>
    </hx-checkbox-group>
  </hx-field>

  <div class="form-actions">
    <hx-button type="submit" variant="primary">Request appointment</hx-button>
    <hx-button type="reset" variant="ghost">Clear form</hx-button>
  </div>
</hx-form>
```

**Component interaction:** `hx-form` observes `hx-field` children and coordinates validation timing. Each `hx-field` passes validation state to its slotted control. `hx-text-input`, `hx-select`, and `hx-checkbox` are all form-associated custom elements — their values submit with the native `<form>` and participate in browser constraint validation.

**Accessibility notes:**

- `hx-field` automatically associates the `label[slot="label"]` with the slotted control using `for`/`id` or `aria-labelledby`
- Help text in `slot="help-text"` is wired to the control via `aria-describedby`
- Validation errors announced to screen readers via `aria-errormessage` on the control
- Do not nest `hx-field` inside `hx-field`; use `hx-checkbox-group` with a `legend` for grouped controls

## Card Layouts

Card compositions are used for article teasers, patient summaries, provider profiles, and content grids. `hx-card` provides the structural shell; `hx-badge`, `hx-avatar`, and `hx-button` populate specific slots.

### Article teaser card

```html
<hx-card variant="default" elevation="raised">
  <hx-image
    slot="media"
    src="/images/cardiology-news.jpg"
    alt="Cardiology research team reviewing data"
    aspect-ratio="16/9"
  ></hx-image>

  <div slot="header">
    <hx-badge variant="info">Cardiology</hx-badge>
    <h2>
      <a href="/articles/heart-failure-study">New Study Links Sleep Apnea to Heart Failure Risk</a>
    </h2>
  </div>

  <p>
    Researchers at Northwell Health found a 40% increased risk of heart failure in patients with
    untreated obstructive sleep apnea. The five-year longitudinal study tracked 12,000 patients
    across three hospital systems.
  </p>

  <div slot="footer">
    <hx-avatar name="Dr. Amara Osei" src="/avatars/osei.jpg" size="sm"></hx-avatar>
    <span>Dr. Amara Osei · March 20, 2026</span>
    <hx-button variant="secondary" href="/articles/heart-failure-study">Read article</hx-button>
  </div>
</hx-card>
```

### Provider profile card

```html
<hx-card variant="outlined">
  <div slot="header">
    <hx-avatar name="Dr. Kenji Watanabe" src="/avatars/watanabe.jpg" size="lg"></hx-avatar>
    <div>
      <h3>Dr. Kenji Watanabe, MD</h3>
      <hx-badge variant="success">Accepting new patients</hx-badge>
    </div>
  </div>

  <dl>
    <dt>Specialty</dt>
    <dd>Internal Medicine, Geriatrics</dd>
    <dt>Location</dt>
    <dd>Main Campus — Building C, Suite 302</dd>
    <dt>Languages</dt>
    <dd>English, Japanese, Mandarin</dd>
  </dl>

  <div slot="footer">
    <hx-button variant="primary">Schedule appointment</hx-button>
    <hx-button variant="ghost">View full profile</hx-button>
  </div>
</hx-card>
```

**Component interaction:** `hx-card` exposes named slots: `media`, `header`, `footer`, and a default slot for body content. Slot content lives in the light DOM, so it inherits your application's base typography styles. Use `@helixui/adopted-stylesheets` to ensure light-DOM content inside the card is styled correctly in Drupal.

**Accessibility notes:**

- Heading hierarchy inside cards must follow document order (`h2` in a card on a page with an `h1`, not `h1` inside the card)
- If the entire card is clickable, prefer a single `<a>` wrapping the heading rather than `onclick` on the card element
- `hx-avatar` provides `alt` text from the `name` attribute when no `alt` prop is supplied explicitly; always verify the derived text is meaningful in context
- `hx-badge` communicates status visually; do not rely on color alone — the text label is required

## Navigation Patterns

Navigation compositions combine `hx-top-nav`, `hx-side-nav`, `hx-breadcrumb`, and `hx-tabs` to create orientation structures for complex healthcare applications.

### Application shell: top nav + side nav

```html
<hx-top-nav aria-label="Primary navigation">
  <a slot="logo" href="/">
    <img src="/logo.svg" alt="Northwell Health Patient Portal" width="160" height="40" />
  </a>

  <nav slot="links" aria-label="Main menu">
    <a href="/dashboard">Dashboard</a>
    <a href="/appointments">Appointments</a>
    <a href="/messages">Messages</a>
    <a href="/records">Health Records</a>
  </nav>

  <div slot="actions">
    <hx-button variant="ghost" aria-label="Notifications (3 unread)">
      <hx-icon name="bell" aria-hidden="true"></hx-icon>
      <hx-badge variant="danger">3</hx-badge>
    </hx-button>
    <hx-avatar name="Sarah Lindqvist" src="/avatars/slindqvist.jpg" size="sm"></hx-avatar>
  </div>
</hx-top-nav>

<div class="app-layout">
  <hx-side-nav aria-label="Section navigation">
    <nav>
      <a href="/appointments/upcoming" aria-current="page">Upcoming</a>
      <a href="/appointments/past">Past visits</a>
      <a href="/appointments/request">Request appointment</a>
      <a href="/appointments/video">Video visits</a>
    </nav>
  </hx-side-nav>

  <main id="main-content">
    <hx-breadcrumb aria-label="Breadcrumb">
      <ol>
        <li><a href="/">Home</a></li>
        <li><a href="/appointments">Appointments</a></li>
        <li aria-current="page">Upcoming</li>
      </ol>
    </hx-breadcrumb>

    <!-- Page content -->
  </main>
</div>
```

### Section navigation with tabs

Use `hx-tabs` for content within a single page view — not for page-level navigation. Tabs are appropriate when all content is available at once and the user needs to switch between views without leaving the page.

```html
<hx-breadcrumb aria-label="Breadcrumb">
  <ol>
    <li><a href="/">Home</a></li>
    <li><a href="/records">Health Records</a></li>
    <li aria-current="page">Medications</li>
  </ol>
</hx-breadcrumb>

<hx-tabs>
  <hx-tab-list aria-label="Medication views">
    <hx-tab id="tab-current" panel="panel-current">Current medications</hx-tab>
    <hx-tab id="tab-history" panel="panel-history">History</hx-tab>
    <hx-tab id="tab-allergies" panel="panel-allergies">Allergies &amp; reactions</hx-tab>
  </hx-tab-list>

  <hx-tab-panel id="panel-current" tab="tab-current">
    <!-- Current medications content -->
  </hx-tab-panel>

  <hx-tab-panel id="panel-history" tab="tab-history">
    <!-- Medication history content -->
  </hx-tab-panel>

  <hx-tab-panel id="panel-allergies" tab="tab-allergies">
    <!-- Allergy list content -->
  </hx-tab-panel>
</hx-tabs>
```

**Component interaction:** `hx-top-nav` manages responsive behavior and mobile menu visibility. `hx-side-nav` collapses to a drawer pattern on narrow viewports. `hx-breadcrumb` is purely structural — it does not manage routing. `hx-tabs` controls `aria-selected`, `aria-controls`, and `aria-labelledby` relationships automatically between `hx-tab` and `hx-tab-panel` elements.

**Accessibility notes:**

- `hx-top-nav` must include `aria-label="Primary navigation"` to distinguish it from other `<nav>` landmarks on the page
- `hx-side-nav` requires its own `aria-label` distinct from the top nav
- `hx-breadcrumb` should be wrapped in a `<nav aria-label="Breadcrumb">` landmark; the last item should have `aria-current="page"`
- `hx-tabs` implements the ARIA Tabs pattern: arrow key navigation between tabs, `Tab` moves focus to the active panel
- Never use `hx-tabs` for top-level page navigation — use `<a>` elements and `aria-current="page"` instead

## Data Display

Data display compositions pair `hx-data-table` with `hx-pagination` and `hx-action-bar` for sortable, filterable, paginated data grids common in clinical and administrative interfaces.

### Patient list with action bar and pagination

```html
<hx-action-bar>
  <hx-text-input
    slot="search"
    type="search"
    placeholder="Search patients..."
    aria-label="Search patients"
  ></hx-text-input>

  <div slot="filters">
    <hx-select aria-label="Filter by status">
      <option value="">All statuses</option>
      <option value="active">Active</option>
      <option value="discharged">Discharged</option>
      <option value="pending">Pending admission</option>
    </hx-select>

    <hx-select aria-label="Filter by unit">
      <option value="">All units</option>
      <option value="icu">ICU</option>
      <option value="cardiac">Cardiac Care</option>
      <option value="oncology">Oncology</option>
    </hx-select>
  </div>

  <div slot="actions">
    <hx-button variant="primary">Add patient</hx-button>
    <hx-button variant="secondary">Export CSV</hx-button>
  </div>
</hx-action-bar>

<hx-data-table id="patient-list" aria-label="Patient list" sortable>
  <hx-column key="mrn" label="MRN" sortable></hx-column>
  <hx-column key="name" label="Patient name" sortable></hx-column>
  <hx-column key="dob" label="Date of birth" sortable></hx-column>
  <hx-column key="status" label="Status"></hx-column>
  <hx-column key="provider" label="Assigned provider" sortable></hx-column>
  <hx-column key="actions" label="Actions" align="end"></hx-column>
</hx-data-table>

<hx-pagination
  total-items="847"
  page-size="25"
  current-page="1"
  aria-label="Patient list pagination"
></hx-pagination>
```

**Wiring the data table with JavaScript:**

```javascript
const table = document.querySelector('#patient-list');
const pagination = document.querySelector('hx-pagination');
const searchInput = document.querySelector('hx-text-input[type="search"]');

// Load initial data
async function loadPatients(page = 1, query = '') {
  const response = await fetch(
    `/api/patients?page=${page}&q=${encodeURIComponent(query)}&per_page=25`,
  );
  const { patients, total } = await response.json();

  // Set table data via property (not attribute — data is not a string)
  table.data = patients.map((p) => ({
    mrn: p.mrn,
    name: `${p.lastName}, ${p.firstName}`,
    dob: new Intl.DateTimeFormat('en-US').format(new Date(p.dateOfBirth)),
    status: p.status,
    provider: p.assignedProvider,
    actions: '', // rendered via column slot template
  }));

  pagination.totalItems = total;
}

// Handle pagination
pagination.addEventListener('hx-page-change', (e) => {
  loadPatients(e.detail.page, searchInput.value);
});

// Handle search (debounced)
let searchTimeout;
searchInput.addEventListener('hx-input', (e) => {
  clearTimeout(searchTimeout);
  searchTimeout = setTimeout(() => {
    pagination.currentPage = 1;
    loadPatients(1, e.detail.value);
  }, 300);
});

loadPatients();
```

**Component interaction:** `hx-action-bar` is a layout container — it slots your search input, filters, and action buttons into a responsive toolbar. `hx-data-table` manages column configuration and sort state; populate it via the `data` property. `hx-pagination` fires `hx-page-change` events with the target page number. Coordinate these three components in your application layer, not inside the components themselves.

**Accessibility notes:**

- `hx-data-table` renders a native `<table>` in its shadow DOM with proper `<th scope="col">` and `aria-sort` attributes managed automatically
- `aria-label` on `hx-data-table` provides the table's accessible name (required when no visible `<caption>` is present)
- `hx-pagination` announces page changes to screen readers via `aria-live` — do not add your own live region
- Search inputs in `hx-action-bar` must have explicit `aria-label` when no visible `<label>` is present

## Overlay Workflows

Overlays — dialogs and drawers — collect focused user input or display supplemental content without navigating away. `hx-dialog` handles modal forms; `hx-drawer` handles side panels.

### Modal form: hx-dialog + hx-form

```html
<!-- Trigger -->
<hx-button id="open-add-medication" variant="primary">Add medication</hx-button>

<!-- Dialog with embedded form -->
<hx-dialog id="add-medication-dialog" aria-labelledby="dialog-title" size="md">
  <span slot="heading" id="dialog-title">Add medication</span>

  <hx-form id="add-medication-form" novalidate>
    <hx-field>
      <label slot="label" for="med-name">Medication name</label>
      <hx-text-input
        id="med-name"
        name="medicationName"
        required
        autocomplete="off"
      ></hx-text-input>
    </hx-field>

    <hx-field>
      <label slot="label" for="med-dose">Dosage</label>
      <hx-text-input id="med-dose" name="dosage" placeholder="e.g. 10mg" required></hx-text-input>
    </hx-field>

    <hx-field>
      <label slot="label" for="med-frequency">Frequency</label>
      <hx-select id="med-frequency" name="frequency" required>
        <option value="">Select frequency</option>
        <option value="once-daily">Once daily</option>
        <option value="twice-daily">Twice daily</option>
        <option value="three-times-daily">Three times daily</option>
        <option value="as-needed">As needed (PRN)</option>
      </hx-select>
    </hx-field>
  </hx-form>

  <div slot="footer">
    <hx-button form="add-medication-form" type="submit" variant="primary">Add medication</hx-button>
    <hx-button id="cancel-medication" variant="ghost">Cancel</hx-button>
  </div>
</hx-dialog>

<script>
  const dialog = document.querySelector('#add-medication-dialog');
  const openBtn = document.querySelector('#open-add-medication');
  const cancelBtn = document.querySelector('#cancel-medication');
  const form = document.querySelector('#add-medication-form');

  openBtn.addEventListener('click', () => (dialog.open = true));
  cancelBtn.addEventListener('click', () => (dialog.open = false));

  // Dialog fires hx-close when dismissed via Escape or overlay click
  dialog.addEventListener('hx-close', () => {
    form.reset();
  });

  form.addEventListener('submit', async (e) => {
    e.preventDefault();
    const data = Object.fromEntries(new FormData(form));
    await saveMedication(data);
    dialog.open = false;
    form.reset();
  });
</script>
```

### Side panel: hx-drawer for detail views

```html
<hx-button id="open-patient-detail" variant="secondary">View patient details</hx-button>

<hx-drawer id="patient-detail-drawer" position="end" size="lg" aria-labelledby="drawer-title">
  <span slot="heading" id="drawer-title">Patient details</span>

  <div class="patient-detail-content">
    <hx-tabs>
      <hx-tab-list aria-label="Patient detail sections">
        <hx-tab id="detail-tab-overview" panel="detail-panel-overview">Overview</hx-tab>
        <hx-tab id="detail-tab-vitals" panel="detail-panel-vitals">Vitals</hx-tab>
        <hx-tab id="detail-tab-notes" panel="detail-panel-notes">Notes</hx-tab>
      </hx-tab-list>

      <hx-tab-panel id="detail-panel-overview" tab="detail-tab-overview">
        <!-- Patient overview content -->
      </hx-tab-panel>
      <hx-tab-panel id="detail-panel-vitals" tab="detail-tab-vitals">
        <!-- Vitals content -->
      </hx-tab-panel>
      <hx-tab-panel id="detail-panel-notes" tab="detail-tab-notes">
        <!-- Clinical notes content -->
      </hx-tab-panel>
    </hx-tabs>
  </div>

  <div slot="footer">
    <hx-button variant="primary" href="/patients/p-001/record">Open full record</hx-button>
    <hx-button id="close-drawer" variant="ghost">Close</hx-button>
  </div>
</hx-drawer>

<script>
  const drawer = document.querySelector('#patient-detail-drawer');
  document.querySelector('#open-patient-detail').addEventListener('click', () => {
    drawer.open = true;
  });
  document.querySelector('#close-drawer').addEventListener('click', () => {
    drawer.open = false;
  });
</script>
```

**Component interaction:** `hx-dialog` is a modal — it traps focus and blocks interaction with content behind it. Use it for actions requiring a decision before continuing. `hx-drawer` is non-modal by default — it slides in alongside main content. Set `modal` on `hx-drawer` if the supplemental content requires exclusive attention. Both components manage their own `aria-modal`, `role`, and focus trap behavior.

**Accessibility notes:**

- `hx-dialog` requires `aria-labelledby` pointing to the heading element in the `heading` slot
- Focus moves to the dialog when opened and returns to the trigger element when closed
- Pressing `Escape` closes both `hx-dialog` and `hx-drawer` — listen for `hx-close` to reset form state
- The `form` attribute on a submit button (e.g., `form="add-medication-form"`) correctly associates the button with a form outside the button's DOM ancestry — this is required when the submit button is in the footer slot

## Feedback Patterns

Feedback compositions communicate system status, validation results, and process outcomes. `hx-alert` handles inline messages, `hx-toast` handles transient notifications, and `hx-banner` handles site-wide announcements.

### Inline alert for form feedback

```html
<!-- Shown after a failed save attempt -->
<hx-alert variant="danger" role="alert">
  <span slot="heading">Unable to save changes</span>
  <p>Your session has expired. Please <a href="/user/login">sign in again</a> and resubmit.</p>
</hx-alert>

<!-- Shown after a successful action -->
<hx-alert variant="success" dismissible>
  <span slot="heading">Appointment scheduled</span>
  <p>
    Your appointment with Dr. Watanabe on March 28 at 2:00 PM has been confirmed. A confirmation has
    been sent to your email.
  </p>
</hx-alert>

<!-- Advisory information with no action required -->
<hx-alert variant="warning">
  <span slot="heading">Incomplete health profile</span>
  <p>
    Some providers require a complete health history before scheduling.
    <a href="/profile/health-history">Complete your health history</a> to access all providers.
  </p>
</hx-alert>
```

### Toast notifications for transient feedback

```html
<!-- Toast container — place once at the application level -->
<hx-toast-region aria-label="Notifications" position="top-end"></hx-toast-region>

<script>
  const toastRegion = document.querySelector('hx-toast-region');

  // Utility to show a toast
  function showToast({ message, variant = 'info', duration = 5000 }) {
    const toast = document.createElement('hx-toast');
    toast.variant = variant;
    toast.duration = duration;
    toast.textContent = message;
    toastRegion.appendChild(toast);
  }

  // After a successful action
  async function handleSave() {
    try {
      await saveRecord();
      showToast({ message: 'Record saved successfully.', variant: 'success' });
    } catch (error) {
      showToast({
        message: 'Save failed. Please try again.',
        variant: 'danger',
        duration: 0, // Persist until dismissed
      });
    }
  }
</script>
```

### Site-wide banner for system notices

```html
<!-- Emergency maintenance notice — place above hx-top-nav -->
<hx-banner variant="warning" dismissible id="maintenance-banner">
  <hx-icon slot="icon" name="wrench" aria-hidden="true"></hx-icon>
  Scheduled maintenance is planned for Sunday, March 29 from 2–4 AM EST. The patient portal will be
  unavailable during this window.
  <a href="/notices/maintenance-march-29">Learn more</a>
</hx-banner>

<hx-top-nav><!-- ... --></hx-top-nav>
```

**Component interaction:** `hx-alert` is static inline content — it renders immediately and persists until removed from the DOM or dismissed (if `dismissible`). `hx-toast` auto-dismisses after `duration` ms and supports a manual dismiss button. `hx-toast-region` manages stacking, animation, and `aria-live` announcement — create one region at the application root and append toasts to it programmatically. `hx-banner` spans full width and is typically placed above the navigation layer.

**Accessibility notes:**

- Use `role="alert"` on `hx-alert` only for critical errors that require immediate attention; it triggers an assertive live region announcement
- For non-critical status messages, use `role="status"` (polite announcement)
- `hx-toast-region` manages its own `aria-live` region — do not wrap it in another live region
- `hx-banner` with `dismissible` stores dismissal state; provide a stable `id` so the preference can be persisted across sessions
- Never rely on color alone to communicate alert severity — the `variant` prop also changes the icon and accessible label

**Drupal Twig (SDC):**

```twig
{# components/system-alert/system-alert.html.twig #}
{{ attach_library('mytheme/helix-alert') }}

{% if message %}
  <hx-alert
    variant="{{ variant|default('info') }}"
    {% if dismissible %}dismissible{% endif %}
    {% if variant == 'danger' %}role="alert"{% elseif variant == 'success' %}role="status"{% endif %}
  >
    {% if heading %}
      <span slot="heading">{{ heading }}</span>
    {% endif %}
    {{ message }}
  </hx-alert>
{% endif %}
```

```html
      <dt>Date of birth</dt>
      <dd>
        <hx-phi-field label="Date of birth" value="1948-03-12" format="date" masked></hx-phi-field>
      </dd>
    </div>

    <div class="patient-info-row">
      <dt>Medical record number</dt>
      <dd>
        <hx-phi-field label="Medical record number" value="MRN-0044821" masked></hx-phi-field>
      </dd>
    </div>

    <div class="patient-info-row">
      <dt>Allergies</dt>

```

**Component interaction:** `hx-phi-field` manages its own masked/unmasked toggle state and emits `hx-reveal` / `hx-mask` events for audit logging. `hx-clinical-status` applies color, iconography, and semantic markup appropriate for clinical priority levels. Wire audit logging to `hx-phi-field` events:

```javascript
document.querySelectorAll('hx-phi-field').forEach((field) => {
  field.addEventListener('hx-reveal', (e) => {
    auditLog.record({
      action: 'phi_revealed',
      field: e.target.label,
      patient: currentPatientMrn,
      user: currentUserId,
      timestamp: new Date().toISOString(),
    });
  });
});
```

**Accessibility notes:**

- `hx-phi-field` with `masked` shows a visually obscured value and provides a toggle button with `aria-label="Reveal [field label]"` / `aria-label="Mask [field label]"`
- `hx-clinical-status` uses `role="status"` for non-critical indicators and `role="alert"` for critical ones — verify these match your clinical workflow requirements
- Patient summary cards should include a visually hidden heading that identifies the patient by name so screen reader users can orient themselves
- Code status and allergy information are safety-critical; never hide them behind a collapsed state without a clearly labeled disclosure control

## Composition Principles

These patterns share common principles worth making explicit:

**One concern per layer.** Components handle their own rendering and accessibility. Compositions coordinate multiple components. Application code handles data, routing, and business logic. Do not put data fetching logic inside components; do not put component-specific accessibility overrides in application code.

**Events over callbacks.** All HELiX components communicate outward via `CustomEvent` with an `hx-` prefix (e.g., `hx-change`, `hx-submit`, `hx-page-change`). Listen to these events at the composition layer to coordinate between components.

**Properties for data, attributes for state.** Pass complex data (arrays, objects, non-string values) via JavaScript properties. Use HTML attributes for boolean flags, string identifiers, and initial state that must be set before JavaScript runs.

**Slot content is light DOM.** Content passed into slots lives in the document's DOM, not inside the component's shadow root. This means it inherits your application styles but not the component's internal styles. Use `@helixui/adopted-stylesheets` when slotted content needs base typography, link styles, or CMS-authored formatting.

**Design tokens, not inline styles.** Override component appearance by setting `--hx-*` custom properties at the appropriate scope. Never use `!important` or inline `style` attributes to force visual changes — these create maintenance debt and bypass the token system.
