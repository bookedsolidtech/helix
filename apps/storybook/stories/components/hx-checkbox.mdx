# `hx-checkbox` — Conformance documentation

> **WCAG 2.2 Level AAA certified** for all 9 component-shippable Success Criteria including 3.3.6 Error Prevention (All), plus 2 peer standards. The canonical APG `checkbox` pattern: <kbd>Space</kbd> toggles, focus is visible, target ≥44×44px, and the indeterminate state is communicated via `aria-checked="mixed"`.

---

## Hero scenario — informed-consent acknowledgement

The most consequential deployment of `hx-checkbox` in healthcare: an informed-consent acknowledgement before a procedure. Every checkbox here is required and the focus order matches the visual order. (The static MDX demo below shows the layout; the disabled-until-all-checked wiring is a consumer-authored pattern — bind the submit button's `disabled` property to a derived "all required boxes checked" state in your app shell.) The pattern lives or dies on AAA target size (2.5.5) — a clinician with motor difficulty must be able to land each checkbox reliably on the first try.

This is the bar. Every checkbox above clears AAA target size at 44×44 CSS px, the focus ring is visible against the form surface, the labels are clickable (so the entire row activates the checkbox), and the keyboard contract — <kbd>Space</kbd> to toggle, <kbd>Tab</kbd> to advance — is exactly what the WAI-ARIA APG `checkbox` pattern specifies.

<SectionHead title="Indeterminate (mixed)" meta="aria-checked=mixed" />

The mixed state communicates "some children of this group are checked." Use as a master toggle in tree-style or grouped selection patterns. Activating an indeterminate checkbox clears the indeterminate state and toggles `checked` — the resulting checked-vs-unchecked outcome depends on the box's current `checked` value; the host typically pairs this with logic that fans the change out to children.

<div style={{ padding: '1rem 0' }}>
  <hx-checkbox
    name="demo_indeterminate"
    indeterminate
    ref={(el) => {
      if (el) el.indeterminate = true;
    }}
  >
    Apply to all members of this care team
  </hx-checkbox>
</div>

<SectionHead title="Required + error" meta="3.3.6 Error Prevention (All)" />

A required checkbox in error state — the consumer attempted submission without acknowledging. Error styling routes through `--hx-checkbox-error-color` (with semantic error-color fallbacks); `hx-text-input` exposes its own `--hx-input-error-color`, so the components share the underlying semantic error palette but each declares its own component-tier hook.

  </hx-checkbox>
</div>
