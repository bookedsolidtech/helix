# `hx-tabs` — Conformance documentation

> **WCAG 2.2 Level AAA certified** for all 9 component-shippable Success Criteria, plus 2 peer standards. Implements the WAI-ARIA APG `tabs` pattern (manual activation variant) — <kbd>Arrow</kbd> keys move the visual focus between tabs without immediately activating, <kbd>Enter</kbd> or <kbd>Space</kbd> activates, and <kbd>Home</kbd> / <kbd>End</kbd> jump to the first / last tab. Each panel is associated with its tab via `aria-controls` + `aria-labelledby`.

---

## Hero scenario — patient chart navigation

The most common deployment of `hx-tabs` in healthcare: chart-section navigation. Six panels, each with a meaningful clinical name, a focused tab indicator, and content rendered inside each panel. Tab into the tablist and use <kbd>Arrow Right</kbd> / <kbd>Arrow Left</kbd> to move between tabs (manual activation — the panel does NOT change until you press <kbd>Enter</kbd>); use <kbd>Home</kbd> / <kbd>End</kbd> to jump to the first or last tab.

This is the contract: tab-key roving (one tab stop for the entire tablist, arrow keys move the inner cursor), manual activation (consumer chooses when the panel switches), and `aria-selected` + `aria-controls` wired through the Shadow DOM so screen readers announce the panel relationship correctly.

<ConsumerObligations
  tag="hx-tabs"
  obligations={[
    <>
      Provide a meaningful name on every <code>hx-tab</code> via slot text. The accessible name is
      the tab label, and the screen-reader announcement is the only navigation aid for non-sighted
      users moving through chart sections.
    </>,
    <>
      Match every <code>hx-tab</code>'s <code>panel</code> attribute to an <code>hx-tab-panel</code>
      's <code>name</code> attribute. The component wires <code>aria-controls</code> +{' '}
      <code>aria-labelledby</code> automatically, but only if the names match — a typo silently
      breaks the screen-reader association.
    </>,
    <>
      Do not nest one tablist inside another. The roving-tabindex model assumes a single tablist on
      a page surface; nested tabs break the composite-widget keyboard contract.
    </>,
    <>
      Use <code>hx-tabs</code> for peer-content navigation (chart sections, settings categories),
      not for primary site navigation. For site nav, use <code>hx-top-nav</code> or{' '}
      <code>hx-side-nav</code> — those expose the URL-route + visited-state surface tabs do not.
    </>,
    <>
      Keep tab labels short (1–3 words). Long labels truncate, the truncation reduces the AAA target
      hit area, and the truncated label may not match the screen-reader announcement.
    </>,
  ]}
