## Hero scenario — sign-in form

The most common deployment of `hx-button`: a primary submit action in a sign-in form, paired with a secondary "Forgot password" ghost button. Tab through the fields below to see the focus ring (`outline 2px solid` against the form surface — clears 2.4.13 Focus Appearance). ## Live state demos

<SectionHead title="Focus visible" meta="2.4.13 Focus Appearance" />

The focus ring is a 2px solid outline rendered on the inner `<button>` part with a contrast ratio ≥3:1 against both the focused and unfocused background. Tab to the button below to see the indicator.

<div style={{ padding: '1rem 0' }}>
  <hx-button variant="primary">Tab to focus me</hx-button>
</div>

<SectionHead title="Disabled state" meta="2.1.3 + APG button.disabledSuppresses" />

A disabled button suppresses both pointer activation AND keyboard activation (`Enter` / `Space`). The `hx-click` event does not fire. Disabled appearance uses reduced opacity, but the contrast ratio is still preserved through the focus path because the underlying `<button>` retains its accessible name.

<div style={{ padding: '1rem 0' }}>
  <hx-button variant="primary" disabled>
    Disabled — no activation
  </hx-button>
</div>

<SectionHead title="Loading state" meta="3.2.5 Change on Request" />

Loading state shows an inline spinner and prevents double-click submission. The spinner is conditionally rendered, so the button width grows when `loading` flips to true — reserve space in your layout (e.g. via `min-width` on the surrounding column) if you need to suppress that shift. The accessible name is preserved so the announcement remains stable for screen readers during the in-flight state.

<div style={{ padding: '1rem 0' }}>
  <hx-button variant="primary" loading>
    Submitting referral…
  </hx-button>
</div>

<SectionHead title="Danger variant" meta="1.4.6 Contrast (Enhanced)" />

The danger variant routes through the semantic `--hx-color-action-danger-bg` and `--hx-color-text-on-error` tokens (the canonical CEM-exposed surfaces; `--hx-color-danger-500` is not a public hx-button hook). The active/hover state pair is AAA-strict; the resting state for the filled danger variant is currently classified at AA per the formal contrast report (the canonical token classification — not all interactive states reach the AAA 7:1 floor). Use sparingly and pair with confirmation flows for destructive operations.

<div style={{ padding: '1rem 0' }}>
  <hx-button variant="danger">Delete patient record</hx-button>
</div>
