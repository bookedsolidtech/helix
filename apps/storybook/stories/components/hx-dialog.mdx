# `hx-dialog` — Conformance documentation

> **WCAG 2.2 Level AAA certified** for all 9 component-shippable Success Criteria, plus 2 peer standards. Implements the WAI-ARIA APG `dialog (modal)` pattern with focus trap, initial-focus management, return-focus on close, and `aria-modal="true"` semantics. The ground-truth canonical modal overlay for the design system.

---

## Hero scenario — destructive confirmation modal

The most consequential deployment of `hx-dialog` in healthcare: a confirmation modal before a destructive operation. Click "Delete patient record" below to open the dialog. While open, focus is trapped inside the modal, the page underneath is inert (cannot receive pointer or keyboard input), and <kbd>Escape</kbd> closes the dialog and returns focus to the triggering button. Initial focus lands on the secondary "Cancel" action so a stray <kbd>Enter</kbd> press defaults to the safe path — a deliberate UX choice for destructive flows.

The contract: focus trap, return focus, inert backdrop, Escape dismissal, initial focus on the safe action. All four behaviors are observable in the dialog above; all four are required by the APG `dialog (modal)` pattern.

        </span>

      <li>
        <span className="hx-apg-kbd-desc">
          <strong>Focus trap</strong> — <kbd className="hx-apg-kbd">Tab</kbd> and <kbd className="hx-apg-kbd">Shift+Tab</kbd> cycle through focusable descendants of the dialog only; the rest of the page is inert.
        </span>
      </li>
      <li>
        <span className="hx-apg-kbd-desc">
          <strong>Escape dismiss</strong> — <kbd className="hx-apg-kbd">Escape</kbd> closes the dialog (unless <code>no-light-dismiss</code> is set, in which case explicit user action is required).
        </span>
      </li>
      <li>

        </span>
      </li>
    </ul>

<ConsumerObligations
  tag="hx-dialog"
  obligations={[
    <>Provide a <code>label</code> attribute (or render a heading into the <code>header</code> slot) — the dialog's accessible name is what screen readers announce on open. Without it, the dialog is announced as "dialog" with no context.</>,
    <>Do not render multiple modal dialogs simultaneously. The APG pattern is single-modal-at-a-time; stacking modals breaks focus trap and makes the inert layer ambiguous.</>,
    <>For dialogs that mediate destructive operations, set the initial-focused action to the <strong>safe</strong> path (Cancel, not Delete). The default Enter activation should never trigger a destructive operation.</>,
    <>Use <code>hx-drawer</code> instead of <code>hx-dialog</code> for non-blocking side-panel patterns. Drawers do NOT trap focus and do NOT inert the underlying page; the two patterns are not interchangeable.</>,
    <>Provide a visible Close mechanism inside the dialog. <kbd>Escape</kbd> alone is not enough — touch-only and switch-control users may not have an Escape key.</>,
  ]}
/>
