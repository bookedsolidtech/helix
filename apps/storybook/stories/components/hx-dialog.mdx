# `hx-dialog` — Conformance documentation

> **WCAG 2.2 Level AAA certified** for all 9 component-shippable Success Criteria, plus 2 peer standards. Implements the WAI-ARIA APG `dialog (modal)` pattern with focus trap, initial-focus management, return-focus on close, and `aria-modal="true"` semantics. The ground-truth canonical modal overlay for the design system.

---

## Hero scenario — destructive confirmation modal

The most consequential deployment of `hx-dialog` in healthcare: a confirmation modal before a destructive operation. Click "Delete patient record" below to open the dialog. The sample below uses `showModal()` so focus is trapped inside the dialog, the page underneath is inert, and <kbd>Escape</kbd> closes the dialog and returns focus to the triggering button. (`show()` opens the dialog non-modally without those guarantees — pick `showModal()` for destructive flows.) Initial focus lands on the first focusable element inside the dialog (the close button by default, or the slotted Cancel button in this layout) — author the dialog content so the safe path is reached first.

The contract: focus trap, return focus, inert backdrop, Escape dismissal, initial focus on the safe action. All four behaviors are observable in the dialog above; all four are required by the APG `dialog (modal)` pattern.

<ConsumerObligations
  tag="hx-dialog"
  obligations={[
    <>
      Provide a <code>heading</code> attribute (or render a heading element into the{' '}
      <code>heading</code> slot) — the dialog's accessible name is what screen readers announce on
      open. Without it, the dialog is announced as "dialog" with no context. (hx-dialog also accepts
      a native <code>aria-label</code> attribute; there is no separate <code>label</code>{' '}
      attribute.)
    </>,
    <>
      Do not render multiple modal dialogs simultaneously. The APG pattern is
      single-modal-at-a-time; stacking modals breaks focus trap and makes the inert layer ambiguous.
    </>,
    <>
      For dialogs that mediate destructive operations, order the slotted footer so the{' '}
      <strong>safe</strong> action (Cancel) appears first — initial focus lands on the first
      focusable descendant, and the default Enter activation should never trigger a destructive
      operation.
    </>,
    <>
      Use <code>hx-drawer</code> for slide-in panel patterns. Drawers also trap focus and inert the
      background by default; both modal-by-default surfaces are interchangeable in that sense, but
      drawers are positioned on the edge of the viewport while dialogs centre.
    </>,
    <>
      Provide a visible Close mechanism inside the dialog. <kbd>Escape</kbd> alone is not enough —
      touch-only and switch-control users may not have an Escape key.
    </>,
  ]}
/>

## Live state demos

<SectionHead title="Notification dialog (non-destructive)" meta="--default" />

Use a non-destructive dialog for confirmation of a successful operation, important notifications, or quick info display. Initial focus lands on the primary acknowledgement button.

<div style={{ padding: '1rem 0' }}>
  <hx-button
    variant="primary"
    onClick={() => {
      const dlg = document.querySelector('#info-dialog');
      if (dlg && typeof dlg.showModal === 'function') dlg.showModal();
    }}
  >
    Show notification dialog
  </hx-button>

  <hx-dialog id="info-dialog" heading="Order placed successfully">
    <h2 slot="heading" style={{ margin: 0, fontSize: '1.125rem' }}>Order placed</h2>
    <p>
      Lab order #LX-249-007 has been transmitted to the reference lab. Results typically return within 24-48 hours.
    </p>
    <div slot="footer" style={{ display: 'flex', justifyContent: 'flex-end' }}>
      <hx-button
        variant="primary"
        onClick={() => {
          const dlg = document.querySelector('#info-dialog');
          if (dlg && typeof dlg.close === 'function') dlg.close();
        }}
      >
        Acknowledge
      </hx-button>
    </div>
  </hx-dialog>
</div>

<SectionHead title="Form dialog" meta="--with-form" />

A dialog containing a form. Wrap the body in a real `<form>` so Enter-to-submit and FormData collection work natively; the footer Save button uses `type="submit"`. The focus trap keeps tab order within the form, and the submit handler closes the dialog before navigating.

<div style={{ padding: '1rem 0' }}>
  <hx-button
    variant="secondary"
    onClick={() => {
      const dlg = document.querySelector('#form-dialog');
      if (dlg && typeof dlg.showModal === 'function') dlg.showModal();
    }}
  >
    Add chart note
  </hx-button>

  <hx-dialog id="form-dialog" heading="Add chart note">
    <form
      id="chart-note-form"
      onSubmit={(e) => {
        e.preventDefault();
        // Persist the form data via your app's mutation layer here, then close.
        document.querySelector('#form-dialog').close();
      }}
    >
      <p style={{ margin: '0 0 1rem 0', fontSize: '0.875rem', color: 'var(--hx-color-text-secondary, #4d5b6b)' }}>
        Notes are timestamped and signed automatically.
      </p>
      <hx-text-input label="Subject" name="note_subject" placeholder="Follow-up — labs reviewed"></hx-text-input>
    </form>
    <div slot="footer" style={{ display: 'flex', gap: '0.5rem', justifyContent: 'flex-end' }}>
      <hx-button
        variant="ghost"
        onClick={() => {
          const dlg = document.querySelector('#form-dialog');
          if (dlg && typeof dlg.close === 'function') dlg.close();
        }}
      >
        Cancel
      </hx-button>
      <hx-button variant="primary" type="submit" form="chart-note-form">Save note</hx-button>
    </div>
  </hx-dialog>
