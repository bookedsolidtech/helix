# `hx-text-input` — Conformance documentation

> **WCAG 2.2 Level AAA certified** for all 9 component-shippable Success Criteria including 3.3.6 Error Prevention (All), plus 2 peer standards (forced-colors, APG keyboard contract). Form-associated via `ElementInternals` so it participates in `<form>` validity, submission, and reset.

---

## Hero scenario — clinical intake form with validation

The most common deployment of `hx-text-input` in healthcare: a clinical intake form where validation errors must be announced **before** the consumer submits, and where the error description is programmatically associated with the field via `aria-describedby`. The MRN field below renders its error UI only once the consumer (or an author-supplied validator) sets the `error` attribute or fills the `error` slot — at that point the input flips to `aria-invalid="true"`, the error text is announced inline with the accessible name, and the error border lights up.

The contract: `hx-text-input` is form-associated via `ElementInternals`, so `<form>.checkValidity()` reflects native constraint validity (`required`, `pattern`, `minlength`, `maxlength`). Author-driven error messaging via the `error` attribute/slot drives the visible aria-invalid state and the `aria-describedby` wiring; together they satisfy 3.3.6 Error Prevention (All) and 2.4.13 Focus Appearance simultaneously.
