## Overview

`hx-form` is a thin orchestration host that wraps (or lives inside) a native `<form>`. It does **not**
replace `<form>` — submission still flows through the real form element, so the submit button and
its `requestSubmit()`/Enter-key behaviour all work natively. `hx-form` listens for that submit event,
collects values via `FormData`, and re-emits typed custom events (`hx-submit`, `hx-invalid`,
`hx-reset`) so consumer code can react without touching the native event surface.

What `hx-form` adds on top of a plain `<form>`:

- Consistent vertical spacing between form fields (`--hx-form-gap`)
- Re-emission of submit/reset as `hx-submit` / `hx-reset` with structured detail
- An `hx-invalid` event listing every failing field at submit time
- A predictable max-width / padding contract via CSS custom properties

### When to Use

- **Patient intake forms** — Collect patient demographics, insurance, and medical history
- **Order entry** — Submit medication orders, lab requisitions, or imaging requests
- **Referral workflows** — Capture referral details, priority, and department
- **Admin configuration** — Settings forms, user profile updates, or system preferences
- **Search/filter UIs** — Multi-field search forms for patient lookup or report generation

### When Not to Use

- **Single input forms** — Use a standalone input with a button for simple search or filter
- **Non-submitting UIs** — If the form never submits data, use semantic HTML (`<div>`, `<section>`)
- **Read-only data display** — Use cards or data grids, not forms

## Accessibility

The Form component meets WCAG 2.2 AA baseline (and AAA on the P0 surface per `aaa-verdicts.json`):

- **Keyboard navigation** — Full support for Tab, Shift+Tab, Enter (submit)
- **Screen reader support** — Proper `<form>` semantics, fieldset/legend for grouping
- **Validation announcements** — Each field's error UI is announced by the individual form control (via its own `aria-invalid` + describedby/ElementInternals wiring) when `hx-form` rejects submission
- **Focus management** — Native HTML5 constraint validation moves focus to the first invalid native control; for ElementInternals-based HELIX controls, your `hx-invalid` handler is responsible for calling `.focus()` on the first failing field

## Properties

| Property     | Type                  | Default | Description                                                                       |
| ------------ | --------------------- | ------- | --------------------------------------------------------------------------------- |
| `name`       | `string`              | `''`    | Name attribute mirrored to the inner `<form>`                                     |
| `action`     | `string`              | `''`    | Form action URL on the inner `<form>` (rarely used with custom submit handlers)   |
| `method`     | `'get' \| 'post'`     | `'get'` | HTTP method for the inner `<form>`                                                |
| `enctype`    | `string`              | —       | Encoding type for the inner `<form>` (multipart forms etc.)                       |
| `novalidate` | `boolean`             | `false` | Disable native HTML5 constraint validation on the inner `<form>`                  |

Layout/gap presets are not attributes; spacing is driven entirely by the `--hx-form-gap` /
`--hx-form-max-width` / `--hx-form-padding` CSS custom properties below.

## Slots

| Slot        | Description             |
| ----------- | ----------------------- |
| `(default)` | Form fields and content |

`hx-form` exposes only the default slot. Action buttons (Submit, Cancel, Reset) are placed in the
default slot alongside the inputs — typically inside a flex `<div>` near the end of the form.

## CSS Custom Properties

Override these tokens to theme the form:

| Property              | Default             | Description                            |
| --------------------- | ------------------- | -------------------------------------- |
| `--hx-form-gap`       | `var(--hx-space-4)` | Gap between form fields                |
| `--hx-form-max-width` | `none`              | Maximum width of the form container    |
| `--hx-form-padding`   | `0`                 | Internal padding of the form container |

## CSS Parts

`hx-form` does not expose any `::part()` shadow parts. Style the form host via the CSS custom
properties above, or target the slotted children directly with global selectors.

## Events

| Event        | Detail                                                                                                | Description                                                                                                       |
| ------------ | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `hx-submit`  | `{ valid: boolean, values: Record<string, FormDataEntryValue \| FormDataEntryValue[]>, formData: FormData }` | Fired by the host after the inner `<form>` submit; `valid` is `false` if any field failed constraint validation |
| `hx-invalid` | `{ errors: Array<{ name: string, message: string }> }`                                                | Fired when one or more fields fail validation at submit time                                                      |
| `hx-reset`   | `CustomEvent` (no detail)                                                                             | Fired when the form is reset                                                                                      |

## Form Participation

`hx-form` does not turn the entire shadow tree into one form-associated control. The inner native
`<form>` is the form root; any field placed inside it — native (`<input>`, `<select>`,
`<textarea>`) **or** form-associated HELIX controls — participates in submission and `FormData`
collection. Form-associated HELIX controls today include:

- `hx-text-input`
- `hx-textarea`
- `hx-select`
- `hx-checkbox`
- `hx-switch`
- `hx-radio-group`

Use these inside `hx-form` for their native form-element participation; other HELIX components do
not auto-register as form values.

## Usage Examples

### Basic Form

`hx-form` only renders an inner native `<form>` when `action` is set. Set `action` (it can target a
real endpoint or a stub like `/submit`) so the submit button has a form to fire — otherwise wrap the
inputs in your own `<form>` inside the default slot.

```html
<hx-form action="/api/referrals" method="post">
  <hx-text-input
    label="Patient Name"
    name="patient-name"
    placeholder="Last, First MI"
    required
  ></hx-text-input>

  <hx-text-input
    label="Medical Record Number"
    name="mrn"
    placeholder="MRN-000000"
    required
  ></hx-text-input>

  <hx-select label="Department" name="department" placeholder="Select department..." required>
    <option value="cardiology">Cardiology</option>
    <option value="neurology">Neurology</option>
    <option value="oncology">Oncology</option>
  </hx-select>

  <div class="hx-form-actions" style="display: flex; gap: 0.5rem; justify-content: flex-end;">
    <hx-button type="submit">Submit Referral</hx-button>
    <hx-button type="reset" variant="ghost">Clear</hx-button>
  </div>
</hx-form>
```

### With Validation Handling

`hx-invalid` reports the full list of failing fields via
`e.detail.errors: Array<{ name, message }>`. Re-look up each offending field by `name` to apply
per-field error UI.

```html
<hx-form id="admission-form" action="/api/admissions">
  <hx-text-input label="Patient Name" name="patient-name" required></hx-text-input>

  <hx-select label="Admitting Department" name="department" required>
    <option value="cardiology">Cardiology</option>
    <option value="neurology">Neurology</option>
  </hx-select>

  <div class="hx-form-actions" style="display: flex; gap: 0.5rem; justify-content: flex-end;">
    <hx-button type="submit">Admit Patient</hx-button>
  </div>
</hx-form>

<script>
  const form = document.getElementById('admission-form');

  form.addEventListener('hx-submit', (e) => {
    e.preventDefault();
    if (!e.detail.valid) return; // hx-invalid already fired with the field list
    console.log('Form data:', e.detail.values);
    console.log('FormData:', e.detail.formData);
    // Submit to API …
  });

  form.addEventListener('hx-invalid', (e) => {
    console.error('Validation failed:', e.detail.errors);

    // Project each error back onto its field by name.
    for (const { name, message } of e.detail.errors) {
      const field = form.querySelector(`[name="${name}"]`);
      if (field) field.setAttribute('error', message);
    }

    // Move focus to the first failing field.
    const first = e.detail.errors[0];
    if (first) {
      const target = form.querySelector(`[name="${first.name}"]`);
      target?.focus?.();
    }
  });
</script>
```

## Design Guidelines

### Form Layout Selection

- **Vertical (default)** — Best for most forms. Each field gets full width, easy to scan.
- **Inline row** — Search bars and single-field forms where label and input sit side-by-side (compose via author CSS flexbox; not a built-in attribute).
- **Multi-column grid** — Multi-column forms for dense data entry like patient demographics (compose via CSS Grid; not a built-in attribute).

### Spacing

Author-side spacing is driven by `--hx-form-gap`. The default of `var(--hx-space-4)` covers most
forms; lower it (e.g. `--hx-form-gap: var(--hx-space-3)`) for compact filter panels, raise it
(e.g. `var(--hx-space-6)`) for forms with complex fields or long labels.

### Button Placement

- Place primary action (Submit) on the left, secondary actions (Cancel, Reset) on the right
- Always use `type="submit"` for the primary button to enable Enter key submission
- Avoid more than 3 action buttons per form

### Validation Timing

- Validate on submit, not on blur (to avoid interrupting user flow)
- Show inline errors after the first submit attempt
- Clear errors when the user corrects the field

### Drupal Form API Integration

`hx-form`, `hx-text-input`, `hx-select`, `hx-textarea`, and `hx-button` are **autonomous custom
elements** — `is="hx-*"` on a native `<textfield>`/`<select>`/`<button>` will not upgrade. Render
the HELIX tags directly from Twig (preferred), or build small `#theme` callbacks that emit them.
The sample below shows a custom-render approach that wraps a Drupal-built form in an `<hx-form>`
via `#prefix` / `#suffix` and delegates the field markup to `#theme` callbacks.

```php
/**
 * Custom form rendered through hx-form.
 *
 * `#prefix` / `#suffix` wrap the form output in <hx-form>; each field
```

### Drupal Behaviors for Form Handling (project-local example)

The shipped `@helixui/drupal-behaviors` package does not include an `hxForm` behavior — `hx-form`
upgrades from its module import alone. The pattern below is a **project-local** behavior layered on
top of the component, kept in a project namespace (`mysite:form-init`) so it never collides with
the package's `hx-*` once keys.

```javascript
/**
 * @file
 * mysite hx-form orchestration behavior (project-local).
 */

(function (Drupal, once, drupalSettings) {
  'use strict';

  // Store listener references so detach() can remove the same fn.
  const handlers = new WeakMap();

  Drupal.behaviors.mysiteFormOrchestration = {
    attach: function (context, settings) {
      once('mysite:form-init', 'hx-form', context).forEach((form) => {
        const formId = form.getAttribute('id');

        const onSubmit = async (e) => {
          e.preventDefault();
          if (!e.detail.valid) return; // hx-invalid already fired

          const { formData, values } = e.detail;
          console.log('Form submitted:', formId, values);

          submitFormStandard(form, formData);
          // …or AJAX/Drupal-AJAX variants
        };

        const onReset = () => {
          form.querySelectorAll('[error]').forEach((field) => {
            field.removeAttribute('error');
          });
        };

        const onInvalid = (e) => {
          console.error('Validation failed:', e.detail.errors);
          for (const { name, message } of e.detail.errors) {
            const field = form.querySelector(`[name="${name}"]`);
            if (field) field.setAttribute('error', message);
          }
          const first = e.detail.errors[0];
          if (first) {
            const target = form.querySelector(`[name="${first.name}"]`);
            target?.scrollIntoView({ behavior: 'smooth', block: 'center' });
            target?.focus?.();
          }
        };

        form.addEventListener('hx-submit', onSubmit);
        form.addEventListener('hx-reset', onReset);
        form.addEventListener('hx-invalid', onInvalid);
        handlers.set(form, { onSubmit, onReset, onInvalid });
      });
    },

    detach: function (context, settings, trigger) {
      if (trigger !== 'unload') return;

      context.querySelectorAll('hx-form').forEach((form) => {
        const refs = handlers.get(form);
        if (refs) {
          form.removeEventListener('hx-submit', refs.onSubmit);
          form.removeEventListener('hx-reset', refs.onReset);
          form.removeEventListener('hx-invalid', refs.onInvalid);
          handlers.delete(form);
        }
      });
      once.remove('mysite:form-init', context.querySelectorAll('hx-form'));
    },
  };

  /**
   * Submit form using standard POST.
   */
  function submitFormStandard(form, formData) {
    const action = form.getAttribute('action') || window.location.href;
    const method = form.getAttribute('method') || 'POST';

    fetch(action, {
      method: method,
      body: formData,
      headers: {
        'X-Requested-With': 'XMLHttpRequest',
      },
    })
      .then((response) => response.json())
      .then((data) => {
        if (data.success) {
          window.location.href = data.redirect || '/';
        } else {
          displayFormErrors(form, data.errors);
        }
      })
      .catch((error) => {
        console.error('Form submission error:', error);
        alert('An error occurred. Please try again.');
      });
  }

  /**
   * Submit form using Drupal AJAX API.
   */
  function submitFormDrupalAjax(form, values) {
    const ajaxSettings = {
      url: form.getAttribute('action'),
      submit: values,
    };

    const ajax = Drupal.ajax(ajaxSettings);
    ajax.execute();
  }

  /**
   * Display server-side validation errors.
   */
  function displayFormErrors(form, errors) {
    Object.keys(errors).forEach((fieldName) => {
      const field = form.querySelector(`[name="${fieldName}"]`);
      if (field) {
        field.setAttribute('error', errors[fieldName]);
      }
    });
  }
})(Drupal, once, drupalSettings);
```

### Multi-Step Form Workflow

**Wizard-style form with step progression:**

```javascript
(function (Drupal, once) {
  Drupal.behaviors.hxFormWizard = {
    attach: function (context) {
      once('hx-form-wizard', '[data-wizard]', context).forEach((wizard) => {
        const steps = wizard.querySelectorAll('[data-step]');
        let currentStep = 0;

        // Initialize wizard
        showStep(currentStep);

        // Listen for form submissions in each step
        steps.forEach((step, index) => {
          const form = step.querySelector('hx-form');

          if (!form) return;

          form.addEventListener('hx-submit', (e) => {
            e.preventDefault();

            // Validate current step
            if (validateStep(form)) {
              // Save step data to sessionStorage
              saveStepData(index, e.detail.values);

              // Move to next step or submit
              if (index < steps.length - 1) {
                currentStep++;
                showStep(currentStep);
              } else {
                submitWizard(wizard);
              }
            }
          });
        });

        function showStep(stepIndex) {
          steps.forEach((step, index) => {
            step.style.display = index === stepIndex ? 'block' : 'none';
          });

          // Update progress indicator
          updateProgress(stepIndex, steps.length);
        }

        function validateStep(form) {
          // Check native HTML5 validation
          const inputs = form.querySelectorAll('[required]');
          let isValid = true;

          inputs.forEach((input) => {
            if (!input.value) {
              input.setAttribute('error', 'This field is required.');
              isValid = false;
            }
          });

          return isValid;
        }

        function saveStepData(stepIndex, data) {
          const wizardData = JSON.parse(sessionStorage.getItem('wizardData') || '{}');
          wizardData[`step_${stepIndex}`] = data;
          sessionStorage.setItem('wizardData', JSON.stringify(wizardData));
        }

        function submitWizard(wizard) {
          const allData = JSON.parse(sessionStorage.getItem('wizardData') || '{}');

          // Flatten all step data
          const combinedData = Object.values(allData).reduce((acc, stepData) => {
            return { ...acc, ...stepData };
          }, {});

          // Submit combined data
          fetch('/api/wizard-submit', {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify(combinedData),
          })
            .then((response) => response.json())
            .then((data) => {
              sessionStorage.removeItem('wizardData');
              window.location.href = data.redirect;
            })
            .catch((error) => {
              console.error('Wizard submission error:', error);
            });
        }

        function updateProgress(current, total) {
          const progress = ((current + 1) / total) * 100;
          const progressBar = wizard.querySelector('[data-progress-bar]');
          if (progressBar) {
            progressBar.style.width = `${progress}%`;
          }
        }
      });
    },
  };
})(Drupal, once);
```
