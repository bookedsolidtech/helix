<section>
  <SectionHead title="Focus trapping in modal surfaces" meta="dialog · drawer" />
  <p className="hx-docs-card-body">
    A modal surface owns the user's focus while open: Tab cycles within, Escape dismisses, and
    the trigger that opened it receives focus when it closes. <code>hx-dialog</code> implements
    this contract directly — call <code>showModal()</code> to guarantee the trap and inert
    backdrop; <code>show()</code> opens non-modal. There is no fallback path to the platform{' '}
    <code>&lt;dialog&gt;</code> element — focus traversal is handled inside the component.
  </p>

    <li>
      <strong>Initial focus.</strong> First focusable element receives focus on open, unless the
      consumer marks one with <code>autofocus</code> (recommended for primary input).
    </li>
    <li>
      <strong>Trap.</strong> Tab past the last focusable wraps to the first; Shift+Tab past the
      first wraps to the last. Focus never escapes to the page beneath.
    </li>
    <li>
      <strong>Dismiss.</strong> Escape closes the dialog. Backdrop click dismissal is on by
      default; set <code>close-on-backdrop="false"</code> to disable it.
    </li>
    <li>
      <strong>Restore.</strong> The trigger that opened the dialog receives focus on close.
      If the trigger has been removed from the DOM, the browser falls back to{' '}
      <code>document.body</code> — author code is responsible for explicitly retargeting focus
      when the trigger may be removed mid-flight (e.g. focus a stable ancestor before deleting
      the row that owned the trigger).
    </li>
  </ol>

    the page's Tab order discoverable instead of flooding the user with N stops per group.
    Roving tabindex is implemented per-component (no shared controller class); the canonical

<section>

  <p className="hx-docs-card-body">
    Every transient surface (popover, menu, drawer, toast action) records the element that
    triggered it and returns focus there on dismissal. This is independent of the modal trap —
    even a non-modal popover restores focus, because losing focus mid-interaction is the
    cardinal sin of dynamic UI.
  </p>

<section>
  <SectionHead title="What we never do" meta="anti-patterns" />
  <ul style={{ fontSize: 14, lineHeight: 1.7, paddingLeft: 20 }}>
    <li>
      <strong>
        <code>outline: none</code> without a replacement.
      </strong>{' '}
      Removing the user-agent ring without authoring a visible substitute fails SC 2.4.7. Period.
    </li>
    <li>
      <strong>Watch the trap boundary on popovers.</strong> <code>hx-popover</code> does trap focus
      while open — that&apos;s deliberate and matches the APG modal-popover pattern.
      A&nbsp;non-modal dropdown disguised as a popover would be a keyboard trap (SC 2.1.2); if you
      need a non-trapping dropdown, use <code>hx-dropdown</code> or compose your own with manual
      focus handling — do not just override the popover&apos;s trap.
    </li>
    <li>
      <strong>Steal focus on render.</strong> A page or component that calls <code>.focus()</code>{' '}
      without user intent disorients screen-reader users. Initial focus is reserved for modal opens.
    </li>
    <li>
      <strong>Move focus on hover.</strong> Hover is not focus. Author components that respond to
      hover with non-focus visual changes only.
    </li>
    <li>
      <strong>Lose focus on async update.</strong> If a re-render removes the focused element, the
      new render must restore focus — not let it fall through to <code>body</code>.
    </li>
  </ul>
</section>
