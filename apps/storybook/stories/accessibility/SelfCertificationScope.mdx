<section>
  <SectionHead title="What is verified" meta="explicit affirmative measurements" />

  <ul style={{ maxWidth: '70ch', lineHeight: 1.7 }}>
    <li>
      <strong>Contrast (1.4.6, 1.4.11)</strong> — measured via the contrast ledger
      (<code>packages/hx-tokens/CONTRAST-REPORT.md</code>) plus axe-core
      <code>color-contrast-enhanced</code> sweep across the rendered Default story DOM. 163/163
      pairings above AA threshold; per-component evidence records the exact foreground/background
      RGB pair and ratio.
    </li>
    <li>
      <strong>Keyboard contracts (2.1.3, APG-keyboard)</strong> — for every interactive primitive
      with an APG pattern, the Default story is exercised with the documented key set and verified
      to match the contract.
    </li>
    <li>
      <strong>Focus indicator (2.4.13)</strong> — measured against the rendered focus state of the
      Default story; verdict records the actual outline and box-shadow values.
    </li>
    <li>
      <strong>Forced-colors</strong> — the source CSS is scanned for forbidden patterns
      (color-bound borders, opacity-based hide-states, non-system color tokens in forced-color
      modes); the Default story is also rendered in forced-colors mode for visual smoke.
    </li>
    <li>
      <strong>Error prevention (3.3.6)</strong> — applies to form-associated{' '}
      <strong>input</strong> components. Submission triggers (aria-pattern=button) are NA — 3.3.6
      is a form-flow contract the consumer app fulfills, not a leaf-component contract. Input
      components must expose <code>ElementInternals</code> + <code>setValidity()</code> so the
      consumer&apos;s form gets native form-validity participation; without setValidity, the
      verdict is Partially Supports.
    </li>
    <li>
      <strong>The remaining 5 criteria</strong> — 1.4.9, 2.3.3, 2.4.12, 2.5.5, 3.2.5 — apply per
      component class; see <a href="/?path=/docs/accessibility-success-criteria--docs">Success Criteria</a> for the per-component
      applicability table.
    </li>
  </ul>
</section>

<section>
  <SectionHead title="What is NOT verified by this cert" meta="honest limits" />

  <ul style={{ maxWidth: '70ch', lineHeight: 1.7 }}>
    <li>
      <strong>Non-default story states.</strong> A component like <code>hx-button</code> ships 49
      stories (variant × tone × size × loading × disabled × icon-only × …). The AAA harness measures
      the Default story. Variant coverage is asserted separately by the story-audit harness
      (<code>scripts/audit-stories.mjs</code>) which renders every story and flags blank canvases,
      contrast failures on rendered text, and axe violations across the whole story surface. The
      two harnesses together cover the surface; the AAA cert badge itself is scoped to the Default
      story.
    </li>
    <li>
      <strong>axe-core ElementInternals coverage gap.</strong> axe-core PR{' '}
      <a href="https://github.com/dequelabs/axe-core/pull/5080">#5080</a> (unmerged) means that
      ElementInternals-attached ARIA on form-associated components is not visible to axe&apos;s rule
      engine. Where this matters, the harness uses DOM-level fallback assertions; see{' '}
      <a href="/?path=/docs/accessibility-axe-element-internals-gap--docs">
        axe-core ElementInternals Gap
      </a>{' '}
      for the documented policy.
    </li>
    <li>
      <strong>Consumer-fulfilled criteria.</strong> Headings hierarchy (1.3.1), reading flow
      (1.3.2), heading purpose (2.4.10), section context (2.4.6) — these depend on consumer
      composition, not the component library. See{' '}
      <a href="/?path=/docs/accessibility-consumer-obligations--docs">Consumer Obligations</a> for
      the partial-applicability contract.
    </li>
    <li>
      <strong>Live runtime behavior under assistive tech.</strong> The harness simulates keyboard
      and inspects DOM; it does not drive NVDA, JAWS, VoiceOver, TalkBack, or Orca. AT smoke runs
      are tracked separately and not part of the cert badge.
    </li>
  </ul>
</section>
